# 📜 架构决策记录 (Architectural Decision Records - ADR)

> **目的**：记录项目历史关键技术选型背后的“**为什么 (Why)**”、权衡考量 (Trade-offs) 与当时接受的局限性。
>
> 💡 **对 AI 代理的约束**：
> 当你认为某处代码实现“不够优雅”或“可以重构精简”时，**必须首先查阅本目录下的 ADR**。
> 严禁在未确认 ADR 背景的情况下，盲目“重构”或“简化”掉团队经过深思熟虑做出的架构妥协。
